# Heuristics

> **Layer 1 — Reusable heuristics** (methodology.md §17)
>
> Anonymised failure patterns, which feed the *error guessing* technique (§5.2) when generating cases. They only come in here **after anonymising**: no names, URLs, data, texts or screenshots of any client. The first three come from the demo's bugs (`examples/demo/`), found on public practice sites.

Format: **component / type of screen → failure pattern → how to test** (module · origin).

| Component / screen | Failure pattern | How to test | Module · origin |
|---|---|---|---|
| Creation endpoint (POST) | A missing required field answers **5xx** instead of 4xx (the invalid input breaks the server instead of being refused) | One request per required field, each one without that field, and another with an empty body; expected 400/422 naming the field (RFC 9110 for 4xx vs 5xx) | `api` · demo, BUG-1 |
| Pages of a web application (especially an SPA) | Every page has the same `<title>` (the application's name): navigation changes the content but not the title (WCAG 2.4.2 A) | In each main view, compare `document.title` with the view's heading; equal titles in different views = Fail | `accessibility` · demo, BUG-2 |
| List or grid of items with an image | Every item shows the same image (the image URL is fixed instead of coming from the item) | Compare the `src` of the images between different items of the same list, not only whether the image loads; repeat with each role, because the defect may affect only one | `functional-web` · demo, BUG-3 |
| Focusable elements (buttons, links, fields) | `outline: none` with no other focus style: the focused element looks the same as when it is not focused (WCAG 2.4.7 AA) | Tab through the page and compare each element focused and not focused; the qa-audit engine does it by pixels (`focus-not-visible`, plan 8.17) | `accessibility` · practice site, plan 8.17 |
| Chat composer (send) | The app says the message failed ("could not send") and hides it, but it was delivered and answered — it appears after reopening the conversation; the user resends and duplicates it | Send, then at once go offline or put the app in the background (0.5–2 s); reopen the conversation and count the messages and answers | `mobile` · real pilot, plan 9.6 |
| Conversation list | The list stops at a fixed number of items (e.g. 20) with no paging, and a conversation with new activity does not move to the top | Create more conversations than one page, scroll to the end; write in the oldest one and reopen the list (also after restarting the app) | `mobile` · real pilot, plan 9.6 |
| Search results | The snippets show the raw highlight markup (`<mark>…</mark>`) and markdown instead of highlighting; no results shows a wrong empty state ("no conversations yet") | Search a word that exists and one that does not; read the snippet as the user sees it (screenshot) | `mobile` · real pilot, plan 9.6 |
| Generated documents from a chat (script, checklist) | The document fills fields the user never gave (duration, relationship, time) and says it was written "from what you told me" | Give a request with few facts; compare every field of the document with the conversation | `mobile` · real pilot, plan 9.6 |
| AI assistant answers | An answer comes in another language than the app and the message (mid-conversation too); a guardrail refusal comes back as an empty bubble | Ask the same questions in a long conversation in the app's language and read the language of each answer; send requests that should be refused and check that the refusal has text | `mobile` · real pilot, plan 9.6 |
| Screen reading for test automation (accessibility tree) | Cards, bottom sheets and multi-line bubbles are missing from the accessibility tree, so an automated reading misses content (a delivered card went unnoticed) | Take a screenshot at each step where the tree may be incomplete and read it before classifying | `mobile` · real pilot, plan 9.6 |
| File attachment in a composer | A file of a type outside the allowed list is refused **silently** (nothing attached, no message), and the error of a previously refused file stays on screen after choosing another one | Attach, in sequence, an allowed file over the size limit, then a file of a forbidden type, then a valid one; after each, read the message shown (screenshot) — each attempt must show its own message or none | `mobile` · real pilot, plan 11.7 |
| Feedback controls on generated answers (👍/👎) | The controls appear only on some answers while the conversation is open (e.g. not on the answer that comes with a generated document, nor on some text answers) and appear on all after reopening | Look at the controls under every answer as it arrives, by kind of answer (text, with a document, short), then reopen the conversation and compare | `mobile` · real pilot, plan 11.7 |
| A real device driven through an accessibility service | A floating accessibility button that the system adds for the service sits over the app's controls on the right edge (e.g. send), and automated taps land on it | After turning the service on, take a screenshot and look at the right edge; turn the service's shortcut off | `mobile` · real pilot, plan 11.7 |
| IBAN field | Accepts spaces when typing but fails validation on submit | Test with and without spaces, with lower case and with the country prefix | `functional-web` · example of methodology §17 |
